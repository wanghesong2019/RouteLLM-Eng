## 关键发现：A6000 就是 GitLab 主机

```
A6000: hostname -I → 172.17.17.50
GitLab: ssh://git@172.17.17.50:2424/...
```

**A6000 = GitLab 所在物理机**。因此 A6000 上 `git clone/push` 直连本机，
无需 33 中转 —— 这是它相对 43 的显著优势。

## 选址决策：维持 43 号机

**理由**：

1. **43 的 4×4090 全空闲**，而 33 和 A6000 的卡都被占用
2. **推理服务已在 43 运行并验证通过**（BERT 加载 1.12s，推理 6.1ms/条）
3. 网关容器也已在 43 部署并全链路验证通过
4. 迁移的成本 > 收益

**已排除的方案**：

| 方案 | 排除原因 |
|---|---|
| 33 上跑推理 | 8×3090 显存全被 vLLM 占用 |
| A6000 上跑推理 | 2×A6000 显存全被占用（GPU 0 是他人进程） |
| 33 构建 + 43 运行 | ✓ **当前采用** —— 33 构建镜像后传输 |

**关于 43 的取舍**：

- 43 到 GitLab 网络不通（需 33 中转同步），这是不便之处
- 但推理与部署形态已跑通，且 43 的 GPU 是唯一空闲的
- 若后续需要频繁同步，可考虑在 43 配置 GitLab 访问（需网络策略调整）

## 遗留

- A6000 的 GitLab 直连优势未利用。若将来 RouteLLM 需要频繁代码迭代，
  可考虑在 A6000 上做开发/构建（它有 GitLab 直连 + 5.2T 磁盘），
  仅把推理与网关留在 43。但当前无此需求。
- GPU 1 的 Qwen3.5-27B-FP8（147 天）若确认不再需要，停掉可腾出 43GB 显存。
